第 04 章

解码层：CRF

CRF 本身不是一类 head。它是叠在任何“逐词打分”的 head 上面的解码层：不再让每个词各自取最大概率，而是给整条标签序列打分，选总分最高的那条。所以它该被当成一个可组合的变量：同一个发射 head，加 CRF 和不加 CRF，各测一遍。

对应脚本 code/ch04_crf.py 实现 CRFHead（约 60 行，没有外部依赖）

一条标签序列 y 的总分，以及它的概率：

s(x, y) = S[y1] + Σt E[t, yt] + Σt>1 T[yt−1, yt] + Z[yn]　　p(y | x) = exp s(x, y) / Σy′ exp s(x, y′)

训练时最大化金标序列的对数概率，分母用前向算法求。预测时用 Viterbi 取总分最高的序列。每个词的置信度，则用前向-后向算法算出的边际概率 p(yt = k | x)，它考虑了整条序列，和局部 softmax 不是一回事。

def _log_z(self, em, mask):                          # 前向算法：所有标签序列的总分（log 域）
    alpha = self.start + em[:, 0]
    for t in range(1, em.shape[1]):
        nxt = torch.logsumexp(alpha.unsqueeze(2) + self.trans + em[:, t].unsqueeze(1), dim=1)
        alpha = torch.where(mask[:, t:t + 1], nxt, alpha)   # 填充位置不更新
    return torch.logsumexp(alpha + self.end, -1)

def loss(self, x, mask, y, boxes):
    em = self(x)                                       # 发射分数 = 线性 head 的输出
    return (self._log_z(em, mask) - self._gold(em, y, mask)).sum() / mask.sum()

§2扁平标签下，CRF 学到了什么

  answer         -0.39     -0.31      0.30     -0.29
  header         -0.30     -0.29     -0.32      0.35
  整行或整列加同一个常数，都会被发射分数的偏置和起止分数吸收，所以只看相对大小：
  对角线比同行、同列的其他格子都高，意思是“倾向于连续同标签”。

学到的东西很简单：对角线约 +0.3，其余约 −0.3，就是“下一个词倾向于沿用上一个词的标签”。它没有学出“question 后面跟 answer”这种有方向的偏好。原因可能有两个。一是几何阅读顺序会把两栏交错，question→answer 的转移在序列里并不稳定。二是扁平标签里也没有 B/I 这类结构约束可学。用 BIO 标签时，CRF 能学到“I-X 前面只能是 B-X 或 I-X”这样的硬约束，扁平标签里没有这层结构。

  CRF 的预测 = Viterbi + 前向-后向（为了给每个词一个边际概率），两者都是沿序列的逐步循环。

单线程延迟：线性 vs 线性 + CRF

两轴都是对数。CRF 的预测包含 Viterbi 和前向-后向。

  • 参数几乎不变：多 24 个数。文件大小和线性 head 一样。
  • 延迟涨了两个数量级：这份实现是 Python 逐步循环，256 个词要几毫秒。复杂度是 O(n·K²)，K=4 时计算量本身很小，慢主要慢在循环开销上，换成编译实现会快很多。即便不优化，256 个词的 5.5 ms 也只是 backbone 单线程时间的约 1.4%。
  • 导出要多费事：Viterbi 和前向-后向是沿序列的动态循环，导出 ONNX 一类格式时要用循环算子或者脚本化。本课没有实测导出。
  • 可组合：CRF 只要求每个词有一组分数、词有先后顺序。所以它也能加在 BiLSTM、树模型、原型法的输出上（取 log 概率当发射分数）。

要点

  1. CRF 是解码变量，不是独立的 head。和同一个发射 head 做有 / 无对照才有意义。
  2. FUNSD 上，线性 + CRF 的宏 F1 高 1.6 个点，实体全对率高 6.4 个点，参数只多 24 个。
  3. 扁平标签下，CRF 只学到“连续同标签”这一条。BIO 那种结构约束，扁平标签里没有。
  4. 边际概率可以当置信度用，校准还行。代价是逐步循环的延迟和导出复杂度。
