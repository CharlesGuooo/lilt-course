第 01 章

实验台：冻结特征与 FUNSD

要比较八类 head，前提是条件完全相同：同一份冻结特征、同一份数据切分、同一套标签、同一个训练预算、同一台 CPU。这一章把这些条件逐项定下来。顺带会看到两个后面反复用到的事实：一维的“相邻”和页面上的“相邻”差得很远；连续几个同标签的词，未必属于同一个实例。

对应脚本 code/ch01_testbed.py 运行 python ch01_testbed.py（第一次会下载 FUNSD 和 LiLT 权重）

§1数据：FUNSD，标签压平

FUNSD 是 199 份扫描的英文表单：官方训练集 149 份，测试集 50 份。每个实体（一组词）带一个标签：question、answer、header 或 other。我们把实体标签直接压到它的每个词上，不加 B-/I- 前缀，得到的就是目标场景那种“字段名 + Other”的扁平词级标签。question/answer/header 当作三个“字段”，other 当作 Other。

官方训练集里每隔 5 份取 1 份做 dev，共 30 份，用来早停和选超参。剩下 119 份训练。测试集 50 份只在最后报告结果时用。空文本的词（FUNSD 里有 890 个）直接丢掉。

§2几何阅读顺序：一维 head 眼里的“相邻”

FUNSD 的 JSON 按实体列词，同一个实体的词天然挨在一起。真实 OCR 不会这样给。为了不让序列 head 白捡这个便宜，我们按几何位置重排：先按纵向中心分行，行内从左到右。

def reading_order(boxes):
    yc = [(b[1] + b[3]) / 2 for b in boxes]
    med_h = statistics.median([max(1, b[3] - b[1]) for b in boxes])
    lines, cur, cur_y = [], [], None
    for i in sorted(range(len(boxes)), key=lambda i: (yc[i], boxes[i][0])):
        if cur and abs(yc[i] - cur_y) > 0.5 * med_h:    # 和这一行第一个词差半个词高以上：换行
            lines.append(cur)
            cur = []
        if not cur:
            cur_y = yc[i]
        cur.append(i)
    if cur:
        lines.append(cur)
    return [i for line in lines for i in sorted(line, key=lambda i: boxes[i][0])]

§3连续同标签 ≠ 同一个实例

扁平标签只告诉你每个词是什么字段，不告诉你哪几个词属于同一个实例。常见的还原办法是把阅读顺序里连续的同标签词并成一段。FUNSD 保留了实体编号，可以直接核对这种办法错多少：

        一个片段里混了 ≥2 个实体： 767 个片段（21.8%）
        一个实体被拆成 ≥2 个片段： 176 个实体（3.4%）
        片段长度（词）p50 2 · p90 8 · p99 32 · 最长 120
  test  字段实体 1,998 个，连续同标签片段 1,241 个
        一个片段里混了 ≥2 个实体： 251 个片段（20.2%）
        一个实体被拆成 ≥2 个片段：  53 个实体（2.7%）
        片段长度（词）p50 2 · p90 10 · p99 51 · 最长 114
  前者：两个相邻的同类实例中间没有 other 隔开，扁平 tag 把它们并成一段；
  后者：多行实体在几何阅读顺序里被别的词隔开。两种情况都说明“连续同标签 ≠ 同一实例”。

两种错误都有。一是“并错”：约五分之一的片段混进了两个以上的实体。比如表格里一列答案上下相邻，中间没有 other 隔开。二是“拆错”：约 3% 的实体被拆成几段，通常是多行的实体被别的词插在中间。这有两个后果：

  • 只用扁平 tag 训练的 head，没有办法学出实例边界。要分实例，要么补 B/I 或实例编号的标注，要么写后处理规则。第 6 章会算出这对实体级指标意味着什么上限。
  • 本课的主指标用逐词 F1，不用实体级 exact match，免得把边界问题和分类能力混在一起。

§4分词与窗口：一次最多 512 个 token

python ch01_testbed.py · §4FUNSD · 冻结 LiLT
  每份文档 subword 数：中位数 263，最多 952；平均每词 1.80 个 subword
  超过 510 个 subword、要切成 2 个窗口的文档：5 / 199

平均每个词切成 1.8 个 subword。199 份里有 5 份超过 510 个 subword。我们把词按顺序切成不重叠的窗口，每个窗口各自前向。代价是窗口边界附近的词看不到另一个窗口的上下文。生产环境可以用带重叠的滑动窗口，再给每个词挑上下文最完整的那一份。不论哪种做法，都要写进输出契约。

§5冻结 LiLT 抽特征，缓存起来

backbone 只跑一遍。每个词取第一个 subword 位置的向量，文本流存最后 4 层，layout 流存最后一层，全部 fp16 落盘。后面所有 head 都在这份缓存上训练和测试。

for a, b in windows_by_tokens([len(p) for p in per_word]):     # 每个窗口 ≤ 510 个 subword
    tok_idx = [t for w in range(a, b) for t in per_word[w]]
    input_ids = [tok.bos_token_id] + [ids[t] for t in tok_idx] + [tok.eos_token_id]
    bbox = [[0, 0, 0, 0]] + [list(boxes[wid[t]]) for t in tok_idx] + [[0, 0, 0, 0]]
    base(input_ids=torch.tensor([input_ids]), bbox=torch.tensor([bbox]), ...)   # hook 取出各层输出
    pos = 1                                                       # 跳过 <s>
    for w in range(a, b):
        text4[w] = torch.stack([taps[("t", i)][0, pos] for i in range(8, 12)]).numpy()
        layout[w] = taps[("l", 11)][0, pos].numpy()
        pos += len(per_word[w])                                   # 跳到下一个词的第一个 subword

§6指标与训练预算

所有 head 用同一套指标。设第 c 类的逐词精确率和召回率是 Pc、Rc：

F1c = 2PcRc / (Pc + Rc)　　宏 F1 = (F1question + F1answer + F1header) / 3
  • 宏 F1：三个字段类的平均，other 不算在内。header 词最少，宏平均能让它的好坏被看见。
  • 实体全对率：金标实体里所有词都标对的比例。它不判断边界，所以不是 exact-field match。
  • ECE：置信度准不准（第 2 章细讲）。按置信度分 10 个等宽区间，算每个区间平均置信度和实际准确率之差，再按词数加权。Guo 等（2017）用的是 15 个区间。

FUNSD 官方报告的是实体级 F1，LiLT 论文的 0.8841 也是。和这里的逐词宏 F1 不是同一个口径，不能放在一起比。

训练预算对所有神经网络 head 都一样，没有针对某个 head 单独调参：

def train_head(make_head, data, view="both", seed=0, lr=2e-3, wd=0.01, bs=8, max_epochs=60, patience=10):
    """
    统一训练预算：AdamW(lr=2e-3, wd=0.01)，每批 8 份文档，最多 60 轮；
    每轮在 dev 上算宏平均 F1，连续 10 轮不涨就停，取 dev 最好的那一轮。
    """

每个 head 用 3 个随机种子（0、1、2）各训练一次，报告均值 ± 标准差。树模型和原型法没有随机性的部分只跑一次。

要点

  1. FUNSD 的实体标签压到词上，就得到扁平的“字段 + Other”标签。119 份训练、30 份 dev、50 份测试。
  2. 按几何位置排阅读顺序，序列 head 才不会白捡“同一实体的词挨在一起”的便宜。
  3. 连续同标签不等于同一实例：约 21% 的片段混了多个实体，约 3% 的实体被拆开。扁平 tag 本身不带边界。
  4. 冻结特征只算一次。传 960 维比 768 维多 25%，last4 多 2.4 倍。backbone 单线程一次前向约 392 ms，后面所有 head 的延迟都拿它来比。
