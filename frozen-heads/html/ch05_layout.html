第 05 章

版面感知 head

表单是二维的。第 3 章看到，一维阅读顺序会把很多二维关系拆散。那么在 head 里显式地再用一次二维位置，有没有用？文献里这一类方法分三条路线：图网络、二维网格、二维相对位置注意力。它们大多是完整的系统，不是可以直接挂在冻结 LiLT 后面的小 head。本章先讲清楚这一点，再测其中最小的一个版本。

对应脚本 code/ch05_layout.py head 定义 Layout2DHead

§1三条路线，三个完整系统

PICK（图）BERTgrid（网格）BROS（二维相对位置）
做法文本片段用 Transformer 编码，对应的图像块用 ResNet50 编码，两者相加作节点；学一个软邻接矩阵，做 1 层图卷积；最后用 BiLSTM + CRF 解码把 BERT 倒数第二层的词向量按词框“涂”进一张 H×W×d 的网格，再用全卷积编码器-解码器做实例分割和框回归本身就是一个预训练语言模型，把文本之间的二维相对位置编进自注意力

监督字符级 IOB像素级分割掩码 + 实例框由下游 head 决定

能不能直接挂在冻结 LiLT 后面不能：要图像、要字符级 IOB思路相近（冻结编码器 + 卷积），但 head 是一整张全卷积网络不能：它本身就是 backbone

图这条路线还有一个更轻的例子：论文 Doc2Graph（Gemelli 等 2022）的节点特征是 spaCy 的静态词向量、一个在 FUNSD 上预训练的 U-Net 视觉特征和归一化坐标，再接图神经网络。它在 FUNSD 上的实体标注 F1 是 0.8225，但分类对象是金标的实体框，不是逐词，没法和本课的数字比。

论文 前面三个系统的效果都有据可查：PICK 在自己的数据集上有消融；BERTgrid 在 1.2 万张发票上，从 Chargrid 的 61.76% 提到 65.48%。但没有一条是“冻结 LiLT + 外挂小 head”的设置，能借鉴的只是设计思路。

§2最小版本：给注意力加二维相对位置偏置

LayoutLMv2 的 spatial-aware self-attention 是在注意力分数上加三项可学的偏置：一维相对位置，以及 x、y 两个方向上的二维相对位置。偏置按注意力头区分，在各层之间共享。论文 vs 代码 论文说用的是框的左上角，HF 和官方代码实际取的是 bbox[..., 0] 和 bbox[..., 3]，也就是左边的 x 和下边的 y。分桶只写在代码里，论文没提。

我们取它最核心的部分，加到第 3 章那个一层 Transformer head 上。其余一切不变，所以两者的差就是“显式二维关系”的边际贡献：

sij = qi·kj / √dh + bx[bucket(cxj − cxi)] + by[bucket(cyj − cyi)]
def rel_bucket(d, side=16):
    """有符号对数分桶：坐标差（0..1000 单位）-> 0..30 的桶号。近处分得细，远处分得粗"""
    b = torch.clamp(torch.floor(2 * torch.log2(1 + d.abs() / 2)), max=side - 1)
    return (torch.sign(d) * b + side - 1).long()

# AttnBlock.forward 里，rel2d=True 时多这几行
cx = (boxes[..., 0] + boxes[..., 2]) / 2                 # 用框的中心
dx = cx[:, None, :] - cx[:, :, None]                     # [B, n, n]：词 j 相对词 i
bias = self.bx(rel_bucket(dx)) + self.by(rel_bucket(dy)) # 每个注意力头一张表
s = s + bias.permute(0, 3, 1, 2)

§4偏置学到了什么

  坐标是 0..1000 的归一化单位；偏置为正 = 更愿意看那个方向、那个距离上的词。

学到的二维相对位置偏置（4 个注意力头取平均）

横轴是相对距离分桶，标的是每个桶的起点（0..1000 单位）。纵轴是加到注意力分数上的偏置。

4 个头平均后，每个桶的偏置都在 ±0.07 以内，曲线也没有清楚的形状（比如“同一行左边的词更重要”）。平均可能会抵消方向相反的头，单个头的偏置这里没有单独看。一个合理的解释是：冻结的 LiLT 特征里已经有 layout 流 12 层的版面信息，再显式给一次坐标，能补的不多。这是推断，不是证明。如果把 head 换成更深的层，或者换一套更依赖二维关系的数据（比如多栏表格），结论可能不同。

单线程延迟：加二维偏置的代价

两轴都是对数。

参数只多 248 个，可延迟几乎翻倍：每次都要算 n² 个坐标差、分桶、查表。输入契约也多了一项：每个词的框。

§6网格化的张量有多大

python ch05_layout.py · §4FUNSD · 冻结 LiLT
  FUNSD 测试集图片中位尺寸 754×1000 像素；把 768 维词向量铺满网格，fp32：
    每 1 像素一格 → 1000×754×768 =   2316.3 MB / 页
    每 4 像素一格 → 250×189×768 =    145.2 MB / 页
    每 8 像素一格 → 125×95×768 =     36.5 MB / 页
  对照：逐词特征（both 960，fp32）中位文档 177 词 ≈ 0.68 MB

如果走 BERTgrid 那条路，把词向量铺满整张页面，原始分辨率下一页就是 2.3 GB，每 8 像素一格也还有 36 MB，是逐词特征的 50 多倍。论文 Chargrid 先按最小字符的尺寸下采样，再插值到 336×256；BERTgrid 论文没有写自己用的分辨率。如果也用 336×256、768 维，一页 fp32 约 264 MB（这是推算）。不管哪种分辨率，这都不是“轻量 CPU head”的量级。

要点

  1. 图（PICK）、网格（BERTgrid）、二维相对位置（BROS）都是完整系统，要图像、要稠密网格，或者干脆替换 backbone，不能直接挂在冻结 LiLT 后面。
  2. 最小的版本（给注意力加二维相对位置偏置）在 FUNSD 上没有可测增益：宏 F1 +0.003，学到的偏置（4 个头平均）都在 ±0.07 以内。
  3. 它的代价是延迟翻倍，而且输入里要多带词框。网格化则是每页几十 MB 到 GB 级的张量。
  4. 建议放在低优先级。只有当前面几类 head 的错误明显集中在“需要二维关系”的样本上（比如多栏表格）时，再做受控对照。
