§1配置：两条流的尺寸

两条流的层数和头数完全一样，只有宽度不同：layout 流的 hidden 和 FFN 都是文本流的 1/4。这个 4 就是配置里的 channel_shrink_ratio。

文本流layout 流
输入词 id（input_ids）框坐标（bbox）
hidden768192
头数 × 每头维度12 × 6412 × 16
FFN 中间层3072768
层数1212
参数从哪来RoBERTa-base，原样不动LiLT 自己预训练
为什么头数必须一样，宽度却可以不一样

BiACM 要把两条流同一层、同一个头的注意力分数逐元素相加（第 4 章）。注意力分数的形状是 [B, 12, L, L]，只和头数、序列长度有关，和每个头多宽无关。所以只要头数和最大长度对齐，layout 流就可以做得很窄。

d_t = cfg.hidden_size                              # 768
d_l = cfg.hidden_size // cfg.channel_shrink_ratio  # 192
print(f"文本流  hidden {d_t}  head_dim {d_t // cfg.num_attention_heads}  FFN {cfg.intermediate_size}")
print(f"layout流 hidden {d_l}  head_dim {d_l // cfg.num_attention_heads}  FFN {cfg.intermediate_size // cfg.channel_shrink_ratio}")

怎么区分哪个参数属于哪条流？LiLT 自己加的参数名都带 layout 或 box_，或者是四张坐标表 x/y/h/w_position_embeddings。其余的参数名和 RoBERTa 一模一样，第 1 章会验证这一点。

def is_layout_param(name):
    """LiLT 自己（layout 流）的参数名都带 layout_ 或 box_ 前缀；其余都是 RoBERTa 文本流"""
    return ("layout" in name) or ("box_" in name) or (".x_position" in name) or (".y_position" in name) \
        or (".h_position" in name) or (".w_position" in name)

§3一次前向

示例发票（common.py 里的 SAMPLE_DOC）有 15 个 segment、32 个词，分词后加上 <s> 和 </s> 一共 66 个 token，所以下面的 L = 66。

张量shape说明
input_ids1×66BPE token id
bbox1×66×4每个 token 的框，坐标已归一化到 0..1000
attention_mask1×66两条流共用
文本 embedding1×66×768第 1 章
layout embedding1×66×192第 3 章
第 12 层文本流输出1×66×768= HF 的 last_hidden_state
第 12 层 layout 流输出1×66×192HF 不返回，要用 hook 取

HF 的 LiltModel 只返回文本流。为了看到 layout 流每一层的输出，common.py 的 run_with_taps() 在两条流的每一层上挂了 forward hook：

for i, layer in enumerate(base.encoder.layer):
    # layer.output / layer.layout_output 是 FFN + 残差 + LayerNorm 之后的输出，也就是这一层的最终输出
    hooks.append(layer.output.register_forward_hook(
        lambda _m, _i, out, i=i: taps["text"].__setitem__(i, out)))
    hooks.append(layer.layout_output.register_forward_hook(
        lambda _m, _i, out, i=i: taps["layout"].__setitem__(i, out)))

→ HF 的 LiltModel 只返回文本流；layout 流最后的 192 维输出被丢掉了（第 6、7 章细讲）。
记住这个差别，第 6、7 章要用

原版仓库的任务头吃的是两条流拼起来的 960 维（768 + 192），论文里的数字都来自这个结构。HF 版只用文本流的 768 维，layout 流最后一层的输出直接丢掉，layout 信息只能通过 12 层 BiACM 间接进入文本流。

要点

  1. LiLT = RoBERTa-base（文本流，124 M）+ LiLT 本体（layout 流，6.1 M）。
  2. 两条流层数、头数相同，layout 流的宽度是文本流的 1/4：192 维，每头 16 维，FFN 768。
  3. 模型只吃三个输入：input_ids、bbox、attention_mask。position_ids 由模型自己算，两条流共用。
  4. HF 的 LiltModel 只返回文本流；要 layout 流的输出得自己挂 hook。
