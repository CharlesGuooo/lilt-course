第 04 章

双流 encoder 与 BiACM

两条流在每一层只交换一样东西：注意力分数。这一章手算一整层 LiLT，验证两条流共用同一张注意力图、各自聚合自己的 value，再用真实权重看 layout 分数到底改变了什么。

对应脚本 code/ch04_biacm.py 运行 python ch04_biacm.py

§1手算第 5 层，和模型实际输出对比

先看普通的单头注意力分数（论文式 4）：

αij = ( xiWQ )( xjWK )⊤ / √dh论文式 (4)

两条流同一层、同一个头各算一个：αT 和 αL。BiACM 把它们相加，作为两条流共同的注意力分数：

α̃Tij = αLij + αTij论文式 (5)
α̃Lij = αLij + DETACH( αTij )　预训练　｜　αLij + αTij　微调论文式 (6)

DETACH 只出现在预训练，第 5 章细讲。下面按微调时的形式手写一整层：

def manual_layer(layer, t, l, use_layout_score=True, use_text_score=True):
    sa = layer.attention.self
    dT = sa.attention_head_size                       # 64
    dL = dT // sa.channel_shrink_ratio                # 16
    qT, kT, vT = split_heads(sa.query(t), dT), split_heads(sa.key(t), dT), split_heads(sa.value(t), dT)
    qL, kL, vL = (split_heads(sa.layout_query(l), dL), split_heads(sa.layout_key(l), dL),
                  split_heads(sa.layout_value(l), dL))
    sT = qT @ kT.transpose(-1, -2) / math.sqrt(dT)    # 文本流的注意力分数 [B,12,L,L]
    sL = qL @ kL.transpose(-1, -2) / math.sqrt(dL)    # layout 流的注意力分数 [B,12,L,L]
    s = (sT if use_text_score else 0) + (sL if use_layout_score else 0)   # BiACM：两张分数相加
    p = s.softmax(-1)                                 # 两条流用的是同一个 p
    ctxT = merge_heads(p @ vT)                        # 用文本的 V 聚合 -> [B,L,768]
    ctxL = merge_heads(p @ vL)                        # 用 layout 的 V 聚合 -> [B,L,192]
    aT = layer.attention.output(ctxT, t)              # dense + 残差 + LN（文本）
    aL = layer.attention.layout_output(ctxL, l)       # dense + 残差 + LN（layout，192 维的一套）
    oT = layer.output(layer.intermediate(aT), aT)     # FFN 768→3072→768
    oL = layer.layout_output(layer.layout_intermediate(aL), aL)   # FFN 192→768→192
    return oT, oL, dict(qT=qT, qL=qL, sT=sT, sL=sL, p=p)

两个容易忽略的细节
  • 两张分数先各自缩放再相加：文本除以 √64 = 8，layout 除以 √16 = 4。
  • 交换的只有分数。V、输出投影、FFN、LayerNorm 两条流各有一套，layout 流的隐状态从头到尾都是 192 维，从来不会被 768 维的文本向量直接加进来。

§2源码里的两个 softmax 其实是同一个

官方实现（modeling_LiLTRobertaLike.py 第 267～298 行，HF 版相同）里写了两份分数、两次 softmax：

tmp_attention_scores = attention_scores / math.sqrt(self.attention_head_size)
tmp_layout_attention_scores = layout_attention_scores / math.sqrt(self.attention_head_size//self.channel_shrink_ratio)
attention_scores = tmp_attention_scores + tmp_layout_attention_scores
layout_attention_scores = tmp_layout_attention_scores + tmp_attention_scores
...
layout_attention_probs = nn.Softmax(dim=-1)(layout_attention_scores)
...
attention_probs = nn.Softmax(dim=-1)(attention_scores)

  逐元素完全相等？ True
  加法可交换，mask 也一样 → 推理时（无 dropout）两条流的注意力概率完全相同。

加法可交换，加的 mask 也一样，所以两份分数逐元素相等，两次 softmax 的结果也相同。准确地说：

  • 前向数值上永远相同，预训练时也一样，因为 DETACH 不改变数值，只改变反向传播。
  • 训练时的区别有两处：两份概率各自过独立的 dropout；预训练时 DETACH 让 layout 那一份的梯度不回流到文本流。
  • 部署推理时可以只算一次 softmax，每层省一个 [B, 12, L, L] 的 softmax 和缓冲区。

§3每一层里，layout 分数占多大分量

用分数的标准差粗略衡量“这张分数表对 softmax 的影响有多大”，看 std(layout 分数) / std(文本分数)：

std(layout 分数) ÷ std(文本分数)，逐层

示例发票，12 个头合在一起算；悬停看两个标准差

浅层到中层（0～8 层）比值在 0.09～0.36 之间，注意力主要由文本决定；最后三层升到 0.54～0.73，版面的分量明显变大。这只是一张发票上的粗略指标，标准差大不等于对结果的贡献大，但趋势很清楚：越往上，版面说话的分量越重。

§5消融：把框打乱 / 把框清零，文本流最后一层变多少

文本和 token 完全不变，只改 bbox，看文本流最后一层输出和原来差多少（逐 token 余弦相似度取平均）：

bbox与原始输出的平均余弦相似度
原始框1.000
15 个 segment 的框随机打乱0.977
全部清零 [0, 0, 0, 0]0.939
参照：完全不要 layout 流（第 1 章 §6 的纯 RoBERTa）0.978

只改框，文本流的输出就变了，差别全部是通过 BiACM 的分数相加传进来的。一个值得注意的对比：框全部清零比完全不要 layout 流偏得更远（0.939 vs 0.978）。单个 token 的框是零，预训练时见过（第 5 章 KPL 会把一部分框换成零）；但整页所有框同时为零，模型没见过，layout 分数照样加进来，起的作用就不可预期了。注意这里量的是“离原输出多远”，不是任务效果。工程上的含义是：少量 token 缺框可以填零，整页拿不到框时不要指望 LiLT 自动退化成纯文本模型。

§6论文的消融：为什么是“分数相加”

论文表 1(a) 在 FUNSD + XFUND（8 种语言）上比较了几种跨模态交互方式，指标是 SER 的平均 F1：

#两条流怎么交互平均 F1
6只用文本流（InfoXLM-base）0.7207
1CAT：只在输出端拼接，中间不交互0.6751
2CAT + Co-Attention（互相用对方的 K、V）0.6276
3CAT + BiACM0.7963

两个反直觉的点：只在输出端拼接（#1）还不如只用文本（#6）；交互更“深”的 Co-Attention（#2）更差。对 #2，论文的解释是这种深度交互破坏了文本流在预训练时的整体一致性。BiACM 只交换分数，不交换表示，文本流的 V、FFN 原封不动，这也是它能和现成文本模型配合的原因。

要点

  1. BiACM 每层只做一件事：两条流的注意力分数（各自缩放后）相加，共用一个 softmax，各自乘自己的 V。
  2. 源码里的两个 softmax 前向数值完全相同；部署时只算一次即可。
  3. layout 分数的相对分量随层数加深而变大（0.13 → 0.73），在示例里最稳定的效果是“同框相吸”。
  4. 只改框就能改变文本流的输出；退化的框（全零）比没有 layout 流偏离更大。
