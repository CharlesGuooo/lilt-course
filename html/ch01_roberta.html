第 01 章

RoBERTa 复习

LiLT 的文本流就是一个原封不动的 RoBERTa-base。这一章只看文本流，把 RoBERTa 的每一步手算一遍。读完你会看到，LiLT 对它一处都没改，只是在注意力分数上多加了一项。

对应脚本 code/ch01_roberta.py 运行 python ch01_roberta.py

§1BPE 分词：一个词会被切成几个 subword

RoBERTa 用的是 byte-level BPE，词表 50265。常见词是一个 token，少见的词、编号、金额会被切成好几块：

python ch01_roberta.py · §1真实分词器 roberta-base
        Invoice → ['ĠInv', 'oice']
  INV-2024-0042 → ['ĠINV', '-', '20', '24', '-', '00', '42']
      $1,250.00 → ['Ġ$', '1', ',', '250', '.', '00']
        Toronto → ['ĠToronto']
          Maple → ['ĠMaple']
  • Ġ 表示这个 subword 前面有空格，也就是一个新词的开头。
  • 特殊 token：<s> = 0（句首，相当于 BERT 的 [CLS]），<pad> = 1，</s> = 2（句尾，相当于 [SEP]）。
  • 输入已经按词切好时（is_split_into_words=True），分词器必须开 add_prefix_space=True，否则每个词开头的 Ġ 不对。
这和 LiLT 有什么关系

一个词被切成几块，这几块都要拿到同一个框。像 INV-2024-0042 这样的编号会占 7 个 token，它们在 layout 流里的坐标完全相同。第 2 章讲怎么对齐。

§2position_ids：RoBERTa 从 2 开始数

这是 fairseq 留下的习惯。位置表的第 0、1 行和 padding_idx = 1 绑在一起，真正的位置从 2 开始，pad 的位置固定是 1。所以位置表是 514 行，等于 512 + 2。

position_ids = cumsum(mask) · mask + padding_idx
python ch01_roberta.py · §2真实分词器
input_ids   : [[0, 5480, 30503, 35, 2], [0, 10566, 35, 2, 1]]
position_ids: [[2, 3, 4, 5, 6], [2, 3, 4, 5, 1]]

第二句比第一句短一个 token，最后补了一个 pad（id 1），它的 position 也是 1。这组 position_ids 只算一次，文本流和 layout 流共用，layout 流有自己的一张 1D 位置表（第 3 章）。

§3文本 embedding = LayerNorm(词向量 + 位置向量 + token_type 向量)

ET = LN(Etoken + P1D)论文式 (1)

论文写的是两项相加。代码里还多加了一个 token_type 向量，但 RoBERTa 的 type_vocab_size = 1，所有位置加的都是同一个常数向量，不影响结论。

E = model.embeddings
manual = E.word_embeddings(ids) + E.position_embeddings(pos) + E.token_type_embeddings(torch.zeros_like(ids))
manual = E.LayerNorm(manual)

注意：文本 embedding 里完全没有 bbox。坐标只进 layout 流。
和 LayoutLM 的第一个区别

LayoutLM 把 2D 位置向量直接加到 768 维文本 embedding 上。LiLT 的文本 embedding 里一个坐标都没有，坐标只进 layout 流。正因为如此，文本流可以整个换掉（第 5 章）。

missing, unexpected = roberta.load_state_dict(text_sd, strict=False)

一个不缺，一个不多。这就是 LiLT 能“换文本模型”的前提：只要另一个模型也是 RoBERTa 结构、尺寸一样，它的权重就能直接填进文本流的位置。

§5手算 RoBERTa 第 0 层（Post-LN）

RoBERTa 沿用 BERT 的 Post-LN 结构：先做残差相加，再 LayerNorm。一层分两个子块：

h1 = LN(x + MHA(x)) h2 = LN(h1 + W2 GELU(W1h1))
MHA 的每个头：softmax( Q K⊤ / √64 ) V论文式 (4)
q, k, v = heads(a.self.query(x)), heads(a.self.key(x)), heads(a.self.value(x))
scores = q @ k.transpose(-1, -2) / math.sqrt(dh)   # [B,H,L,L]
probs = scores.softmax(-1)
ctx = (probs @ v).permute(0, 2, 1, 3).reshape(B, L, D)
h1 = a.output.LayerNorm(a.output.dense(ctx) + x)                # ① attention + 残差 + LN
ffn = layer.output.dense(layer.intermediate(h1))                 # ② 768→3072(GELU)→768
h2 = layer.output.LayerNorm(ffn + h1)                            #    + 残差 + LN

Q/K/V      1x12x66x64   (batch, heads, seq, head_dim)
scores     1x12x66x66
层输出      1x66x768
手算 == RobertaLayer 输出 ? True

把 scores 这一行记住：[1, 12, 66, 66]，每个头一张 L × L 的分数表。第 4 章的 BiACM 就是在这张表上再加一张同样形状的 layout 分数表。

§6预告：同样的文本权重，加上 layout 流以后输出变了多少

python ch01_roberta.py · §6真实权重
纯 RoBERTa vs LiLT 文本流（最后一层）逐 token 余弦相似度：平均 0.978，最低 0.913
两者用的是同一套文本权重，差别全部来自 BiACM 加进来的 layout 注意力分数（第 4 章）。

平均 0.978，说明 layout 流对文本表示是“微调”而不是“重写”。变化最大的是 Ġchairs（0.913）、ĠAC（ACME，0.929）、Ġlamps（0.945），都在商品行和抬头里。只看一张发票，不宜过度解读哪些 token 一定变得多；能确定的是，这些差别全部来自 layout 分数，因为两边的文本参数一模一样。

要点

  1. LiLT 的文本流和 RoBERTa-base 参数名一一对应，load 进去一个不缺、一个不多。
  2. RoBERTa 的 position_ids 从 2 开始，pad 位置是 1，位置表 514 行；这组 position_ids 两条流共用。
  3. 文本 embedding 里没有任何坐标信息，坐标只进 layout 流。
  4. 每层的注意力分数是 [B, 12, L, L]，BiACM 就加在这里。
