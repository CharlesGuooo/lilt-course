第 02 章

输入准备

OCR 引擎给出的是“一块块文字 + 像素框”。这一章把它变成模型要的三个张量：input_ids、bbox、attention_mask。中间有三件事要处理：坐标归一化、框的粒度、subword 对齐。

对应脚本 code/ch02_inputs.py 运行 python ch02_inputs.py

§1OCR 的原始输出：segment + 像素框

课程用的示例是 common.py 里手工构造的一张发票，页面 850 × 1100 像素。每个 segment 是 OCR 给出的一行或一块文字，带一个像素框 (x0, y0, x1, y1) 和一个 FUNSD 风格的标签（HEADER / QUESTION / ANSWER / OTHER）。

§2坐标归一化到 0..1000

不同扫描件的分辨率不一样，同一张发票扫成 300 dpi 和 72 dpi，像素坐标差好几倍。所以先把坐标换成“占页面宽高的千分比”，取整：

x′ = ⌊ 1000 · x / W ⌋　　y′ = ⌊ 1000 · y / H ⌋　　再截到 [0, 1000]
python ch02_inputs.py · §2示例数据
  像素 (60, 140, 170, 160)  →  [70, 127, 200, 145]
  像素 (660, 460, 760, 480)  →  [776, 418, 894, 436]
越界会直接报错

模型的坐标 embedding 表只有 1024 行（max_2d_position_embeddings = 1024）。忘了归一化、或者框超出页面导致坐标大于 1023，查表时就是 IndexError（在 GPU 上是 device-side assert）。官方的 normalize_bbox 没有截断；common.py 多加了 min(1000, max(0, ·))。第 3 章的交互图可以试一下坏框。

§3词级框 vs segment 级框

一个 segment 里通常有好几个词。给每个词什么框？有两种做法：

python ch02_inputs.py · §3示例数据
  Invoice      segment框 [70, 127, 200, 145]   词框 [70, 127, 152, 145]
  No:          segment框 [70, 127, 200, 145]   词框 [164, 127, 200, 145]
  March        segment框 [682, 127, 847, 145]   词框 [682, 127, 741, 145]
  15,          segment框 [682, 127, 847, 145]   词框 [752, 127, 788, 145]
  2024         segment框 [682, 127, 847, 145]   词框 [800, 127, 847, 145]

论文和官方 FUNSD 代码都用 segment 框：同一行里的所有词共享一个框。论文 2.1.2 节给的理由是，很多 OCR 引擎根本不给细粒度的词框。（示例里的“词框”是按字符数把 segment 框横向切开估出来的，只是演示。）

代价是：同一个 segment 里的词，在 layout 流眼里坐标完全一样，只能靠 1D 位置区分先后。第 3 章 §3 会验证这一点。

§4subword 对齐：每个 token 继承它所属词的框和标签

分词以后，一个词可能变成好几个 token。规则很简单：

  • 框：同一个词的所有 subword 都用这个词的框。
  • 标签：只给词的第一个 subword 打标签，其余 subword 标 -100，交叉熵会忽略它们。
  • 特殊 token：<s>、</s> 的标签也是 -100，框见 §5。
点一个 segment，看它变成了哪些 token

§5特殊 token 的框：论文和代码不一样

</s> 的框

论文 2.1.2 节写的是：[CLS] 用 (0,0,0,0,0,0)，[SEP] 用 (1000,1000,1000,1000,0,0)，[PAD] 用全 0（论文这里的 6 元组包括宽和高）。官方 FUNSD 微调代码 run_funsd.py 里，<s> 和 </s> 都填 [0,0,0,0]。

python ch02_inputs.py · §5示例数据
  官方 FUNSD 代码          ：<s> [0, 0, 0, 0]   </s> [0, 0, 0, 0]
  论文 2.1.2 节写法        ：<s> [0, 0, 0, 0]   </s> [1000, 1000, 1000, 1000]

预训练代码没有公开，所以没法确认预训练用的是哪种。实际做法是：微调和推理保持一致，用了哪种就一直用哪种。

§6最终送进模型的张量

python ch02_inputs.py · §6真实分词器
  input_ids       1x66       torch.int64
  bbox            1x66x4     torch.int64
  attention_mask  1x66       torch.int64
  • position_ids 不用传。模型用 input_ids 自己算（第 1 章 §2），两条流共用。
  • word_ids 不进模型，但要留着，推理后用它把 token 预测还原成词。
  • 如果用支持 boxes 参数的分词器（tokenizer(words, boxes=boxes)），它内部做的就是 §4 这套对齐。

要点

  1. 坐标先归一化到 0..1000 的整数，和页面分辨率无关；超过 1023 会越界报错。
  2. 官方做法用 segment 框：同一行的词共享一个框，行内先后只能靠 1D 位置区分。
  3. subword 继承所属词的框；标签只给首个 subword，其余和特殊 token 标 -100。
  4. </s> 的框论文和代码不一致；微调和推理保持一致即可。
