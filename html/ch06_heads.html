第 06 章

输出与任务头

12 层之后，两条流各留下一份特征。原版仓库把它们拼成 960 维交给任务头，HF 版只用文本流的 768 维。这一章先讲清这个差别，再看两个下游任务的头：SER（逐 token 分类）和 RE（关系抽取）。

对应脚本 code/ch06_heads.py 运行 python ch06_heads.py

§1两条流的最终输出

python ch06_heads.py · §1真实权重

  layout流 1x66x192   ← HF 的 LiltModel 不返回它，这里是用 hook 取出来的
  HF last_hidden_state 1x66x768  pooler_output 768 维（取 <s> 过 dense+tanh）

pooler_output 是 <s> 的向量过一层 dense + tanh，给文档分类这类整篇级任务用；SER 和 RE 都用不到。

§2原版 vs HF 的 token 分类头

原版代码（modeling_LiLTRobertaLike.py）里，分类头的输入是 hidden_size + hidden_size // channel_shrink_ratio：

...
sequence_output = torch.cat([sequence_output, layout_outputs], -1)

  原版 LiLTRobertaLikeForTokenClassification.classifier = Linear(in_features=960, out_features=7, bias=True)
用 HF 版时要知道的事

用 HF 权重微调出来的模型，和论文报告数字的那个模型，严格说不是同一个结构：HF 版的 layout 信息只能通过 12 层 BiACM 的注意力分数间接进入文本流，最后一层的 192 维 layout 输出没有直接进头。差多少要在自己的数据上量。如果想要原版结构，可以像 common.py 那样用 hook 取出 layout 输出，自己拼接。

§3SER：逐 token 分类 → 词级标签 → 实体

SER（Semantic Entity Recognition）给每个词打 BIO 标签。从 logits 到实体分三步：

  1. token 级：特征 [1, 66, 960] 过线性层得到 [1, 66, 7]，每个 token 取 argmax。
  2. 词级：每个词只看它第一个 subword 的预测，和训练时只给首个 subword 打标签对应（第 2 章 §4）。这一步要用 word_ids。
  3. 实体：B-X 开头、后面连续的 I-X 合并成一个 X 实体。比如 Invoice=B-QUESTION、No:=I-QUESTION 合成一个 QUESTION 实体 “Invoice No:”。
word_pred, seen = {}, set()
for i, wid in enumerate(enc["word_ids"]):
    if wid is not None and wid not in seen:      # 每个词只取第一个 subword
        seen.add(wid)
        word_pred[wid] = LABELS[pred[i]]

§4RE：判断两个实体之间是不是 key-value 关系

RE（Relation Extraction）在 SER 的实体之上做：哪个 QUESTION 对应哪个 ANSWER。官方 re.py 的结构：

  • 候选对：一篇文档里所有 (question, answer) 组合。训练时，标注里有的是正例，其余全是负例。
  • 实体表示：只用实体第一个 token 的特征，加上类型向量。
  • 打分：biaffine = 双线性项 hᵀWt（捕捉“这对组合”）+ 线性项 V[h; t]（各自的倾向），输出 2 类。
python ch06_heads.py · §4head 未训练，只看 shape
  question 实体 4 个，answer 实体 5 个 → 候选对 20 个（所有 question × answer）
  head 表示 20x1920 → MLP → 20x384
  biaffine 打分 → 20x2   （是 / 不是 key-value 对）
  例： 'Invoice'→'INV-2024-0042', 'Invoice'→'March', 'Invoice'→'Jane', 'Invoice'→'42' ...

示例发票里 4 个 QUESTION × 5 个 ANSWER = 20 个候选对。示例数据本身没有关系标注；按常识，真正的 key-value 对大约 5 个（Bill To: 同时对应姓名和地址两行），其余 15 个都是负例。负例远多于正例，是 RE 的常态。

要点

  1. 原版任务头吃 960 维（文本 768 + layout 192）；HF 版只吃文本 768 维，结构和论文不同。
  2. SER：token logits → 每个词取首个 subword → BIO 合并成实体，全程依赖 word_ids。
  3. RE：所有 question × answer 组合当候选，实体用首 token 特征 + 类型向量，biaffine 二分类。
  4. 论文的 FUNSD 结果：从 RoBERTa-base 出发，加上 layout 流，F1 0.665 → 0.884。
