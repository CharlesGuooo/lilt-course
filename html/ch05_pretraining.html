第 05 章

预训练

LiLT 的卖点是：layout 流只在英文文档上预训练一次，就能接到别的语言的 RoBERTa 上用。这一章看它靠哪四件事做到：权重可拼接、DETACH 挡梯度、三个预训练任务、文本流学习率放慢 1000 倍。

§1一个 LiLT checkpoint = RoBERTa 权重 + lilt-only 权重

官方仓库的 gen_weight_roberta_like.py 就是一次字典合并：

config['channel_shrink_ratio'] = 4
config['max_2d_position_embeddings'] = 1024
text_model = torch.load(opt.text)
text_model = {k.replace('roberta.', 'lilt.'): v for (k, v) in text_model.items()}
lilt_model = torch.load(opt.lilt)
total_model = {**text_model, **lilt_model}

脚本演示了这件事反过来也成立：把文本流整个换成另一套（这里用随机权重代替），layout 流的参数一个都不动。

能换的前提
  • 层数、头数、最大长度要一样（12 层、12 头、512）。论文 3.1 节说，这保证了 BiACM 能正常工作：每层都有对应的分数表可以相加。
  • hidden 也得是 768。gen_weight_roberta_like.py 直接沿用文本模型的 config，layout 流的宽度按 hidden_size // 4 算出来；如果换成 hidden 1024 的 large 模型，layout 流就变成 256 维，21 MB 的 lilt-only 权重就装不进去了。
  • 文本模型必须是 RoBERTa 结构（键名能从 roberta.* 改成 lilt.*）。

§2DETACH：预训练时挡住 “layout 损失 → 文本流” 的梯度

α̃Lij = αLij + DETACH( αTij )论文式 (6)，预训练

前向数值不变（第 4 章 §2），变的是反向：layout 那一份分数里的 αT 被当成常数，layout 分支的损失不会通过它回传到文本流的 WQ、WK。脚本造了一个只依赖 layout 分支的损失，量一下文本流 WQ 收到多少梯度：

s_for_layout = sL + (sT.detach() if detach else sT)   # 论文公式 (6)
p = s_for_layout.softmax(-1)
layout_ctx = p @ sh(sa.layout_value(l), 16)
loss = layout_ctx.pow(2).mean()                        # 随便一个只依赖 layout 分支的损失
loss.backward()

  detach=False  文本 W_Q 的梯度范数 2.17e-01   layout W_Q 的梯度范数 3.73e-01
  detach=True   文本 W_Q 的梯度范数 0.00e+00   layout W_Q 的梯度范数 3.73e-01

为什么要挡：论文的说法是，为了让 LiLT 尽可能和不同的现成文本模型配合，预训练时不能让非文本的梯度去改文本流，要保持文本流的整体一致性。换句话说，layout 流要学会适应一个“固定的 RoBERTa”，而不是和预训练时那个文本流互相迁就、绑在一起。微调时去掉 DETACH，两条流一起训。

§3三个预训练任务的标签

MVLM：遮词预测（Masked Visual-Language Modeling）

随机选 15% 的 token：其中 80% 换成 <mask>，10% 换成随机词，10% 不变。layout 信息保持不变。模型用输出特征在整个词表上预测原 token。和 BERT 的 MLM 一样，只是多了版面信息可以参考。

     Ġlamps     → 随机词   目标：在整个词表上预测原 token

KPL：关键点定位（Key Point Location）

把整个页面（归一化后是 1000 × 1000 的正方形）等分成 7 × 7 = 49 个区域。随机选 15% 的框：80% 换成全零，10% 换成同 batch 里的随机框，10% 不变。模型要用三个独立的分类头，分别预测原框的左上角、右下角、中心点落在 49 个区域里的哪一个。

点一个框，看它的三个关键点落在哪个区域

蓝色是示例发票的 15 个 segment（归一化坐标，所以页面被压成了正方形，内容都在上半部分）。橙色格子是三个分类目标。

def region(x, y, n=7):
    col = min(n - 1, x * n // 1001)
    row = min(n - 1, y * n // 1001)
    return row * n + col

为什么预测区域而不是精确坐标：OCR 的框本来就有误差，要求精确回归反而在惩罚噪声。改成 49 类分类放宽了标准，论文说这样效果更好。

CAI：跨模态对齐识别（Cross-modal Alignment Identification）

收集被 MVLM 和 KPL 处理过的 token-box 对，再加一个二分类头判断：这一对还对得上吗？被换成随机词或随机框的标 0（没对齐），保持原样的标 1（对齐）。这逼模型去学“这个词应该出现在这个位置吗”，也就是跨模态的一致性。

§4文本流学习率放慢 1000 倍

如果所有参数用同一个学习率，预训练时文本流也在变，layout 流就会一直追着这个“变化中的文本流”去耦合，换一个文本模型就不灵了。论文的做法是把文本流的学习率大幅调低（论文 2.3 节）：

base_lr = 2e-5
text_params   = [p for n, p in model.named_parameters() if not is_layout_param(n)]
layout_params = [p for n, p in model.named_parameters() if is_layout_param(n)]
optim = torch.optim.AdamW([
    {"params": layout_params, "lr": base_lr},
    {"params": text_params,   "lr": base_lr / 1000},
], weight_decay=1e-2)

有意思的是完全冻结（#6）不是最好的：文本流稍微动一点，比一点不动更好。微调阶段则回到统一学习率，DETACH 也去掉。

要点

  1. LiLT checkpoint = 改了键名的 RoBERTa 权重 + 21 MB 的 lilt-only 权重；换文本模型要求层数、头数、长度、hidden 都对齐。
  2. DETACH 不改前向数值，只让 layout 分支的梯度不回流文本流；只在预训练用。
  3. 三个任务：MVLM 学文本，KPL 学“东西在哪”（49 区域分类），CAI 学“文字和位置对不对得上”。
  4. 预训练时文本流学习率放慢 1000 倍，比统一学习率和完全冻结都好。
